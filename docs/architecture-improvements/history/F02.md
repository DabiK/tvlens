## Défaut

Une écriture refusée par le disque à la fin d’une session était absorbée sur trois maillons : le cœur, le store et le runtime. La fin pouvait annoncer une archive complète alors qu’un état final manquait.

| Situation | Avant (base `0940c45`) | Après (`828307e`) | « Avant » établi par |
|---|---|---|---|
| Fin par HTTP, `session.json` refusé | `archived: true`, pas d’`errors`, journal vide | `archived: false`, `errors` nommant le fichier, journal | Test rouge |
| Arrêt de l’hôte serveur, même refus | Dernière issue `archived: true`, journal vide | Issue non archivée, journal ; session listée interrompue au redémarrage | Test rouge |
| Fin d’une session Mac, même refus | Journal vide | Ligne de journal nommant le fichier ; session listée interrompue | Test rouge |
| Pendant la session, sauvegarde refusée | L’état publié avec la description d’un passage ne le disait plus ; après une sauvegarde aboutie, l’ancien message restait | Dit tant qu’aucune sauvegarde n’a abouti, effacé quand une sauvegarde aboutit | Test rouge |
| Archive en lecture seule, question dont l’écriture est refusée, puis fermeture | `archived: true`, journal vide | `archived: false`, `errors` nommant `deep-answers.json` | Sonde hors dépôt |
| Session dont le manifeste n’a jamais été écrit | Listée `archived`, marquée d’avant les manifestes, date de clôture inventée | En cours si elle est en mémoire, interrompue sinon, sans date de clôture | Tests rouges et sonde sur `37ccea6` (règle inchangée depuis la base) |

Dans tous les cas, le fichier refusé garde son dernier contenu confirmé : l’écriture passe par un fichier temporaire puis un renommage, ce qui existait déjà.

## Déroulé

1. **Exploration en lecture seule**, puis approbation. Bornes fixées : pas de fsync ni de promesse face à une coupure de courant ; pas de nouvel état de liste ni de nouvelle surface IPC ou HTTP ; pas de regroupement des écritures ni de réécriture du cycle de vie ; visibilité par le statut du cœur, les erreurs et le journal des hôtes, et l’état « interrompue » de la liste.
2. **Développement**, commit `e0a9a55`. Six tests ajoutés, deux défauts de conception corrigés avant le commit (voir plus bas).
3. **Première review** sur `e0a9a55` : les deux axes demandent des changements pour le même constat bloquant, déduit à la lecture.
4. **Correction**, commit `37ccea6`. Constat reproduit avant d’être corrigé ; deux tests ajoutés.
5. **Deuxième review** sur `37ccea6` : deux validations. Un constat non bloquant sort du périmètre du ticket (liste d’une session sans manifeste) ; il fait l’objet d’une exploration complémentaire en lecture seule, puis d’une approbation limitée à trois fichiers.
6. **Complément**, commit `828307e`. Deux tests ajoutés, une attente existante adaptée.
7. **Troisième review** sur `828307e` : deux validations, sans constat bloquant.
8. **Contrôle du merger** : suite Node complète sur `828307e`. L’intégration est retenue le temps de cette phase documentaire.

## Ce qui a échoué en route

| Échec | Diagnostic | Correctif |
|---|---|---|
| Premier jet : barrière passée seulement quand le manifeste n’était pas encore `archived` | Une archive ouverte en lecture seule reçoit quand même les questions posées dessus ; leur refus serait resté silencieux | Barrière passée à chaque fermeture ; cas ajouté au test HTTP ; sonde avant/après |
| Premier jet : barrière limitée aux écritures passées par le store | Un refus du port d’archive lui-même n’atteint pas la chaîne du store ; seul le cœur le sait | Le runtime honore aussi `saveError` ; cas ajouté ; mutation de contrôle |
| Test du cœur : première assertion verte sur l’ancien code | Hasard de calendrier, un balayage publiait un état après coup | Description du passage retenue par une barrière explicite ; le test est alors rouge pour la bonne raison |
| `e0a9a55` : archive rouverte puis reprise, `manifest.json` seul refusé, fin annoncée `archived: true` sans erreur | Le runtime décidait d’écrire le manifeste final d’après l’état du manifeste confirmé, qui venait d’une vie antérieure et disait déjà `archived` | `37ccea6` : « archivée » devient un fait de la vie en cours du runtime ; toute vie qui a capturé écrit son manifeste final |
| `e0a9a55` : même prémisse pour la pause tardive | Après une fin refusée, une pause pouvait écrire `archived` | Couvert par le même correctif ; mutation de contrôle |
| `e0a9a55` : le runtime écrivait lui-même le manifeste confirmé à la réouverture | Frontière : seul le store doit déplacer sa confirmation | Le store adopte le manifeste lu |
| `37ccea6` : réponse `archived: false` mais session listée `archived` quand aucun manifeste n’existe | Règle de bibliothèque antérieure aux sessions durables, hors de la propriété du ticket | Complément approuvé, `828307e` |
| Attente existante devenue fausse après le complément | Une session coupée réduite à ses médias était attendue `archived` | Attente passée à `interrupted`, valeur que le même test attend déjà quand le manifeste existe ; adaptation validée par les deux reviews |

Incidents de procédé, sans effet sur le code :

- un passage dans la fenêtre Electron native a démarré pendant des mutations temporaires de la bibliothèque ; il a été écarté et relancé sur le commit, arbre intact avant et après ;
- une commande de vérification s’est arrêtée avant toute copie de fichier (découpage de mots de l’interpréteur de commandes) ; elle a été relancée sans rien modifier.

## Alternatives

| Alternative | Exécutée ? | Pourquoi écartée |
|---|---|---|
| Barrière conditionnelle à l’état du manifeste | Oui, premier jet | Silencieuse pour une archive en lecture seule |
| Barrière limitée au store | Oui, premier jet | Aveugle à un refus du port d’archive |
| Décision d’après l’état du manifeste confirmé | Oui, `e0a9a55` | Lit le manifeste d’une vie antérieure |
| Comparaison d’identité entre manifeste demandé et confirmé | Non, proposée par la review | Deux pauses tardives séparées par un refus pouvaient réécrire `live` sur une fin confirmée |
| Compter le manifeste dans la barrière | Non, écartée à la conception | Un refus ancien du manifeste aurait interdit de tenter le manifeste final |
| Inscrire le refus parmi les erreurs de fermeture du runtime | Non | Les hôtes rapportent déjà le rejet de `archive()` : la ligne aurait été doublée |
| Émission dédiée quand le statut de sauvegarde change | Non | Cadence d’émission laissée à F03 |
| fsync, nouvel état de liste, nouvelle surface | Non | Exclus par l’approbation |

## Ce qui a été exercé

- **Node, simulation.** Store et runtime réels sur répertoire temporaire, cœur avec un port d’archive de substitution, hôte serveur réel derrière son transport HTTP, hôte Mac réel chargé avec un substitut d’Electron. Les refus du disque sont simulés sur l’écriture du fichier temporaire ; un refus de création de répertoire ou de renommage n’est pas exercé.
- **Mac natif.** Test Electron générique en mode simulé, données synthétiques et répertoires isolés, lancé par le développeur : trois passages retenus, un écarté. Seul le dernier a tourné sur un commit figé, arbre intact avant et après. Il couvre le chemin normal (archivage, ouverture et reprise d’une archive), pas l’échec disque. Aucun contrôle natif indépendant n’est enregistré pour F02 à la date de rédaction.
- **Couture Mac.** L’échec disque y est testé pour `session.json` seulement ; le cas sans manifeste n’y a pas de test dédié.
- **TV, VPS, fournisseurs.** Non exercés.

## Limites et dettes

| Sujet | Origine | Suite proposée |
|---|---|---|
| Pas de fsync : coupure de courant après le renommage non couverte | Approbation d’exploration | Hors périmètre |
| Archive reprise dont le manifeste est refusé pendant toute la vie reprise : la liste garde l’ancienne archive et ses anciens totaux, alors que la fin a répondu `archived: false` | Review spécification, troisième passe ; non figé par un test | Ticket de suivi : figer la ligne ou traiter le manifeste périmé |
| Fermer une session interrompue ouverte en lecture seule répond `archived: true` côté serveur, la liste restant interrompue | Dette antérieure, comportement inchangé | Ticket de suivi : répondre d’après le manifeste confirmé |
| Les commentaires des deux hôtes ne mentionnent pas le cas sans manifeste | Review standards, troisième passe | À compléter à l’intégration ou au prochain ticket qui touche ces fichiers |
| La liste des rétentions est recopiée du cœur | Review standards, troisième passe | L’exporter du cœur le jour où une rétention est ajoutée |
| Le store exclut le manifeste de la barrière par son nom | Review standards, troisième passe | Passer l’exclusion par l’appelant s’il en apparaît un second |
| Deux fermetures qui se chevauchent partagent leur issue ; une pause lancée entre le manifeste final et sa confirmation pourrait réécrire `live` | Reviews, deuxième passe ; déduit, non reproduit | Non atteignable tant que les hôtes sérialisent leurs transitions ; coalescer ou documenter |
| Refus de création de répertoire ou de renommage non exercés | Reviews, deuxième passe | Cas optionnel dans le test du store |
| Côté Mac, aucune trace dans la fenêtre : journal et liste seulement | Borne de l’approbation | Ticket d’interface si une alerte est voulue |
| Pendant la session, un refus de sauvegarde n’apparaît qu’au prochain état publié | Développeur | F03 |
| Une nouvelle demande d’archive ne retente que l’état et le manifeste ; aucun hôte ne redemande | Review standards, première passe | Aucune : un fichier de l’hôte doit être réécrit par lui |
| Un état sauvegardé juste après un refus porte encore l’ancien message d’erreur ; inerte à la réouverture | Review standards, première passe, non retenu | Aucune |
| Le client TV ignore le corps des réponses de fin et de fermeture | Lecture des reviews ; TV non exercée | Ticket d’interface distinct |
| Le test Electron générique écrit ses captures hors du répertoire temporaire privé | Développeur ; script antérieur, hors diff | Ticket séparé |
