## Défaut

Une description d’images qui échouait, quelle qu’en soit la cause, laissait le passage sans description pour de bon.

| Situation | Avant (base `474346a`) | Après (`2cec0b1`) | « Avant » établi par |
|---|---|---|---|
| Connexion Codex perdue en plein tour, voie libre | Passage `partial`, vision `error`, un seul tour | Un second tour sur un processus reconnecté ; passage `ready`, aucune erreur publiée | Test rouge, vrai client Codex sur faux App Server |
| Même perte deux fois de suite | Un seul appel | Deux appels exactement, puis perte finale comptée | Test rouge |
| Échéance de l’adaptateur atteinte | Erreur non distinguée, définitive | Marquée si c’est la raison de son signal, ou un tour que Codex confirme interrompu sans détail | Test rouge |

Les tests qui caractérisent ne distinguent pas la base du commit : ils fixent ce que le changement ne doit pas faire. Ce sont les mutations qui montrent qu’ils échouent quand une garde manque.

## Déroulé

1. **Exploration en lecture seule.** Chaîne d’appels tracée de la capture au client Codex et à l’agent local. Constat : aucun chemin ne remet un passage en file après un échec de vision, et les erreurs de transport n’ont pas de code. Un plan minimal et cinq décisions à trancher sont proposés. Ni la fréquence des échecs ni la forme réelle des erreurs d’un Codex n’ont été observées.
2. **Plan amendé par la supervision avant toute écriture.** Sept points : redemande unique et en ligne, sans file ni délai ; classification dans `codex-perception.cjs` seulement, par marqueur et liste de messages exacts ; refus vérifiés avant toute autre preuve, causes et cas composés compris ; un `TimeoutError` quelconque ne permet rien ; HTTP 5xx passager et 4xx définitif ; échéance abaissable seulement ; compteurs distincts, absents avant leur premier événement et restaurés bornés.
3. **Développement.** Le fichier de tests est écrit d’abord et joué sur la base : 16 échecs sur 19. Le cœur puis l’adaptateur sont modifiés ; la première exécution est verte, 19 sur 19, sans correction du code produit. Seize fichiers de tests existants sont ensuite joués un à un, sans modification.
4. **Mutations.** Vingt-et-une gardes sont retirées une à une ; une mutation passe inaperçue (voir plus bas). Le test des refus est complété, cinq mutations sont ajoutées, le rouge est rejoué sur la base avec le fichier de tests final, puis le commit `2cec0b1` est créé et le fichier dédié rejoué dessus.
5. **Review standards** sur `2cec0b1` : validée à la première passe, quatre constats non bloquants.
6. **Suspension puis reprise de la vague.** D’après le fichier de reprise du run, lu sans rien exécuter : la supervision a suspendu la vague faute d’espace disque, puis l’a reprise. La review standards, déjà validée sur ce même commit, a été conservée ; le code n’a pas changé entre les deux reviews.
7. **Review spécification** sur `2cec0b1` : validée à la première passe, cinq constats non bloquants.
8. **Documentation**, ce commit : ADR et historique seulement.

## Ce qui a échoué en route

Aucun échec du code produit n’a été rencontré. Deux défauts concernaient les tests.

| Échec | Diagnostic | Correctif |
|---|---|---|
| Au premier rouge, un test échoue sur la base par une `TypeError` au lieu d’une assertion | Le test lisait la cause d’une erreur marquée, que la base ne produit pas | Lectures de cause rendues tolérantes ; rouge rejoué, mêmes 16 échecs |
| Première passe de mutations : « 5xx élargi à 4xx » n’est pas détectée | Le veto 4xx couvre cette mutation. Surtout, les entrées du veto n’étaient vérifiées que comme erreurs de premier niveau, définitives par défaut : aucune n’était discriminée séparément | Chaque refus est aussi présenté comme cause, puis comme cause de la cause, d’un message de la liste blanche, avec une cause inconnue comme contrôle positif. Les cinq mutations ajoutées sont détectées |

## Ce qui a été exercé

- **Node, simulation.** Cœur avec des doublures de perception, de média et d’archive. Vrai client Codex derrière un faux App Server en mémoire : aucun binaire Codex lancé, répertoire d’authentification inexistant. Vrai tuyau Codex devant un processus Node local qui ne répond rien. Vrai agent local avec une doublure de requête HTTP : aucune requête ne sort du processus.
- **Mac natif.** Non exercé : le changement ne touche ni l’hôte Mac ni sa fenêtre.
- **TV, VPS, fournisseurs.** Non exercés.
- **Mesures.** Aucune latence, aucune fréquence d’échec. Les tests comptent des appels et lisent des statuts.
