## Défaut

Un processus Codex fermé pouvait encore tourner quand son remplaçant démarrait, et ce qu’une session avait ouvert lui survivait.

## Déroulé

1. **Exploration en lecture seule.** Chaînes d’appels tracées des deux hôtes jusqu’au transport, et du client MCP externe jusqu’au modèle d’inspection. Le rapport sépare ce que le code établit de ce qui est déduit : l’appel MCP tardif, le lanceur mort et le spawn sans tubes sont alors des déductions. Il demande un fichier hors de la fiche, le processus principal Mac : le pont et le runtime de session ne se connaissent pas, seul l’hôte sait qu’une session finit.
2. **Gate d’exploration.** Plan approuvé et amendé :
   - la fermeture distingue une disparition confirmée d’une sortie incertaine, et aucune reconnexion n’a lieu sans confirmation ;
   - l’inspecteur refuse avant le cache et après l’attente, en gardant l’objet exposé ;
   - le processus principal Mac est alloué, pour une révocation synchrone et le refus d’ouvrir un contexte pendant une fermeture ;
   - un test sur le vrai processus principal et un test sur le vrai runtime de surveillance sont exigés ;
   - aucune interface de client définitif sans appelant.
3. **Développement.** Le fichier de tests est écrit d’abord et joué sur la base : 11 rouges sur 11, le processus se termine seul. Le transport, le client, le pont, le runtime de session et l’hôte Mac sont modifiés ; la première exécution est verte, 11 sur 11. Le test de surveillance passe avec la seule barrière du client : son runtime ne reçoit qu’un commentaire. Un douzième test relie le vrai client au vrai transport. Vingt-deux fichiers existants sont joués, sans modification.
4. **Commit `5532d04`.**
5. **Reviews sur `5532d04`.** Spécification : validée, quatre constats non bloquants. Standards : changements demandés pour un constat bloquant, déduit par lecture et non reproduit, plus cinq constats non bloquants.
6. **Correction.** Le test « hôte à part » est écrit d’abord et reproduit le constat sur `5532d04`. Le client tient la boucle pendant ses attentes ; le transport ne change que d’un commentaire. Quatre constats non bloquants sont traités dans le même commit (voir plus bas).
7. **Commit `be16029`.**
8. **Reviews sur `be16029`.** Les deux valident : deux constats non bloquants côté standards, trois côté spécification.
9. **Documentation**, ce commit : ADR et historique seulement.

## Ce qui a été exercé

- **Node, vrais processus.** Le vrai transport lance des programmes Node à la place de Codex : polis, sourds à SIGTERM, lanceurs qui meurent en laissant un survivant détaché de tout tube. Un hôte Node à part, sans autre travail, porte le vrai client sur le vrai transport.
- **Node, doublures.** Une fausse application serveur derrière le vrai client, dont la sortie est donnée par le test ; un spawn remplacé pour l’enfant sans tubes et pour le groupe qui ne meurt pas. Dans ce dernier cas aucun signal ne quitte le test.
- **Runtimes réels sur agents simulés.** Runtime de session sur un dossier temporaire, runtime de surveillance avec le vrai agent Codex sur doublure.
- **Hôte Mac sans Electron.** Le vrai processus principal et le vrai preload derrière un substitut d’Electron, agents simulés, minuteurs réels ; le pont est appelé en HTTP sur la boucle locale, comme le fait le serveur MCP.
- **Non exercés.** Vrai Codex, fournisseurs, fenêtre Mac native, TV, VPS, Windows, arrêt réel de l’hôte serveur, suite globale.
- **Mesures.** Aucune durée, aucune latence, aucun nombre de tâches système.

## Organisation de la boucle

D’après le contrat de coordination de la boucle, lu sans rien exécuter : après F03, l’utilisateur a autorisé deux sessions actives au plus. Les sujets F04 et F08 puis F09 et F10 ont avancé par vagues parallèles ; F05, F06 et F07 sont séquentiels. F05 part de la base cumulative qui contient F01 à F04 et F08 à F10 ; la dépendance « bloqué par #4 » de la fiche était un ordre de coordination, que ce plan remplace. Chaque sujet a son arbre de travail, son fichier de tests dédié et un ADR numéroté comme lui. Aucun test commun n’est modifié ; les développeurs lancent des tests ciblés, et la suite globale, les essais Mac natifs et la vérification cumulative reviennent au merger.

Le processus principal Mac n’était pas dans la fiche : le gate d’exploration l’a alloué explicitement, pour la seule composition du pont et la fin de session.

Les consignes de chaque phase étaient suivies d’un script de supervision collé à leur suite. Ni le développeur ni les reviews ne l’ont exécuté : il n’appartient pas au sujet.
