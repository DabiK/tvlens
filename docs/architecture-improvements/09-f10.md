# F10 — Une petite plage vidéo charge le clip entier

## Contexte

Audit Opus/Astra du code local TV Lens au13octobre2026, incluant les évolutions non publiées. P3 ; Optimisation de lecture. Origine : Astra A7.

Le lecteur demande bytes=0-0, mais le store lit tout le WebM et la voie HTTP rematérialise le buffer.

## Preuves et limites

Double local : clip2Mo chargé pour une réponse206 de1octet. Clips courts et taille d’ingestion bornée : priorité modérée.

Sources à explorer avant modification : `adapters/local-store.cjs:181`, `server/http.cjs:145`.

## Direction approuvée

Lire/diffuser seulement la plage demandée derrière le contrat existant, en préservant statuts, contrôles de chemin et annulation du client.

## Critères d’acceptation

- [ ] Une Range valide lit/diffuse seulement les octets nécessaires, sans matérialiser tout le clip.
- [ ] Statuts 206/416/indisponible, tailles, contrôles de chemin, annulation et comportement Electron/HTTP restent compatibles.
- [ ] Tests plages/EOF/invalides/concurrence/suppression et octets réellement lus ; pas de serveur média supplémentaire.

## Dépendances

Blocked by: https://github.com/DabiK/tvlens/issues/8 — ordre séquentiel de coordination et base intégrée requise

La boucle développe un seul sujet à la fois. Base actualisée après intégration/review du précédent.

- adapters/local-store.cjs (médias)
- server/http.cjs (réponse média)
- tests Range

Les changements hors de ces zones doivent être motivés avant modification ; préserver tous les autres travaux.

## Boucle de livraison

1. Session Opus5.5 ultracode fraîche : exploration forcée avec outils de lecture seulement, chaîne d’appels et tests proposés.
2. Implémentation minimale et régression rouge/verte, puis tests hors ligne proportionnés.
3. Reviews indépendantes conformité et architecture, corrections jusqu’à validation.
4. Intégration locale et vérification par la supervision ; sujet suivant ensuite.

## Contraintes

Travaux locaux uniquement pendant l’absence de l’utilisateur : aucun déploiement, push, accès TV/VPS, fournisseur de l’application ou modification d’authentification/données utilisateur. Pas de framework, DB ou modèle nouveau. Conservation jusqu’à suppression, garde de contexte, citations, files bornées, atomicité, idempotence et confinement failclosed restent intacts. Mesures synthétiques identifiées ; aucun gain de latence inventé.
